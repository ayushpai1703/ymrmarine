## Go/No-Go decision framework — managed PostgreSQL migration

| Gate | Condition | Status |
|---|---|---|
| 1. Business need | A specific, named PostgreSQL-only feature requirement exists | **Not met** — no such requirement identified |
| 2. Cost justification | Projected PostgreSQL option beats an optimized MySQL option on recurring cost | **Not met** — `cloud-cost-projection.md` shows no recurring-cost advantage |
| 3. Risk tolerance | Engineering capacity exists for a 2–4 week migration effort with staging rehearsal | Not evaluated — moot given gates 1–2 |
| 4. Safety prerequisites | RCA-00 (cost) and RCA-08 (backups) resolved on the *current* platform first | **Not met** — both are still open |

**Decision: No-Go.** All four gates would need to flip for this to become a Go, and the first two — the ones that actually matter — show no basis for migrating today. Revisit this framework if a concrete PostgreSQL feature requirement is ever identified.
